# 演出编辑器（第六台）：把 EFFECTS 当数据编

入口 `/editors/effects.html`。前五台编辑器分别管**资产、姿势、房间、集成、材质源码**，
这一台管**时间**：同一段演出，改一个强度不必改源码再等 HMR，而是拖一个点、看一帧。

## 0. 结论

- 演出是**数据**：`TimelineShow`（轨道 + 关键帧）→ `params(t)` → `EffectSpec`。导出的是纯数据代码，
  贴回内容仓即可，没有运行时依赖。
- 两条播放路径**刻意分开**：播放走真实调度器 `stage.effects.play()`；拖动走手动定位。
  验证「运行时行为」必须用前者，因为后者绕开了 effects 的末帧补写与临时 pass 拆装。
- 轨道 key 的 `t` 是**归一化相位**（0–1），不是秒。改时长时曲线形状不变——这是刻意选择，
  演出通常是「比例」而不是「绝对时刻」。
- ASCII 演示是**同一条参数总线上的一个写入者**，不是第二条播放通道。

## 1. 为什么不能直接调代码演出

`src/kits/shows.ts` 里的 `chargeBurst()` 是代码：6 条轨道全部硬编码在一个数组里。调参流程是
「改数字 → HMR → 重新触发 → 看画面」。这条流程有三个问题：

1. **看不见形状**。`uRimPulseStrength` 在 0.32 冲到 1.7 再回落到 0.77，读代码只能靠脑内画图。
2. **不能定格**。effects 的相位只前进、不能 seek（`EffectHandle` 没有 `seek`，因为 `params(t)` 的
   契约就是「只接收时间」，不支持回退）。要看第 0.7 秒那一帧，只能重播并祈祷按得准。
3. **试错成本落在源码上**。任何一次试验都会留下 diff。

编辑器把这三件事一次性解决：曲线可视化、任意 scrub、试验只存在于内存（导出时才落成代码）。

## 2. 两种播放路径

| | 播放（▶） | 拖动 / 暂停（scrub） |
| --- | --- | --- |
| 走什么 | `stage.effects.play(specFrom(t))` | 自己 `stage.onFrame()` 每帧写参数 |
| 谁写参数 | 演出调度器（写入者 `show:<id>`） | 编辑器（写入者 `preview`） |
| 临时 pass | effects 负责建链 / 出链 | 编辑器自己 `post.insert` / `post.remove('shock')` |
| 末帧 | 参数**留在最后一帧的值**（`restore` 只拆 pass 与 overlay，不回写参数） | 游标停在最后一帧，参数留在最后一次写入 |
| 用途 | 验「真实运行时行为」 | 定位、逐帧对比、调曲线 |

**「播完角色没了」不是 bug**：默认这段演出的末帧 `uDissolve = 0.995`（刻意不推满，全消会像崩了），
所以播完看到的是「几乎全消」的残影（`screenshots/fx-end-dissolved.png`）。按 **■ 停止** 或把
时间轴拖回 0，参数回到相位 0，角色立刻回来；按 ▶ 重播也会在 t=0 这一帧写回 0。

**为什么不能合并成一条**：`scan` 需要「相位可任意跳」，而 effects 的相位是单调时钟。让 effects
支持 seek 会污染它的契约（`params(t)` 之外还要维护内部状态回滚），代价远大于收益。分两条反而
让两边都简单：播放路径永远走真实调度器，定位路径永远只写参数。

三种状态机的形态：

```
play  --(播放结束)-->  idle
scrub --(▶)-->         play
play  --(拖点 / 拖刻度尺)--> scrub
```

`idle` 是「演出播完、参数留在末帧」的静止态——这时拖动时间线仍然有效（会切到 scrub）。

## 3. 数据模型

```ts
interface TimelineShow {
  id: string;
  duration: number;            // 秒，只影响「相位 → 秒」的显示与播放
  loop: boolean;
  onEnd: 'restore' | 'keep';
  colors: Record<string, string>;   // 曲线表达不了的颜色，按常量写
  shock?: { from: number; to: number; strength: number; width?: number; color?: string };
  tracks: TimelineTrack[];
}

interface TimelineTrack {
  id: string;                  // 必须等于参数 id（uRimPulseStrength…）
  ease?: 'smooth' | 'linear';
  keys: { t: number; v: number }[];   // t 归一化 0–1，按 t 升序
}
```

映射到 `EffectSpec` 的规则（`src/kits/timeline.ts`）：

- `params(t)` = 每条轨道 `sampleTrack(track, t)`，再叠加 `colors` 常量与冲击波轨道的区间判断。
- `post(ctx)` 只在 `t ∈ [shock.from, shock.to]` 时插入冲击波 pass（层 C）。
- `overlay` 不参与——演出是「作用在角色上」，不是「盖一层 UI」。
- `onEnd: 'restore'` 让 effects 在末帧把所有参数写回基线；`keep` 则留在末值。

**未声明的参数不写**：每帧写入前先 `params.has(id)`，没有就只在右栏标红。否则 `ParamBus` 会自动
建一个同名参数并每帧发 notice，画面看起来「有效果」其实是写进了一个没人读的槽——这类假成功比
报错更难查。

## 4. 交互

- **拖点**：左右拖改 `t`，上下拖改 `v`（纵向范围按轨道值域自动收紧，不固定 0–1）。
- **双击轨道空白**：在当前位置加一个关键帧。
- **右键点**：删点。
- **拖刻度尺**：scrub（同时会自动退出 ASCII 演示——那是另一套语境）。
- **◀ 帧 / 帧 ▶**：按 1/30 s 步进，等价于动画的时间分辨率。
- **速度 1× / 0.5× / 0.25×**：缩放传给 `stage.render(dt)` 的 `dt`。注意它同时让角色 idle 变慢，
  不是「只慢演出」——调试时这是想要的（看清一帧），但不能当成产品功能。
- **自动取景**：重新框住角色的脸与胸口。

## 5. 右栏

| 分组 | 内容 |
| --- | --- |
| 演出 / SHOW | id、时长、循环、`onEnd` |
| 颜色常量 | 边缘光 / 溶解色，直接写 `uRimPulseColor` / `uDissolveColor` |
| 冲击波 | 起止相位、强度（层 C，`afterTonemap`） |
| ASCII 流动 | 8 个滑杆 + 字符色 + 演示开关（见 §6） |
| 轨道 | 参数名（带 datalist 补全）、缓动、复制 / 删除轨道 |
| 参数状态 | 当前所有相关参数的**是否已声明 + 当前值**，未声明标红 |
| 导出 | 生成自包含的 `EffectSpec` 工厂代码 |

`参数状态`这张表是排错主入口：**轨道存在但标红 = 模块没装上**（`characterModules` 漏了，
或者参数 id 拼错）。这时画面没反应是正确行为，不是 bug。

## 6. ASCII 演示

`ascii-flow` 是层 A 模块（`src/shader/modules/ascii-flow.ts`），它按**屏幕空间**切格子把模型表面
换成流动的字形。演示开关做三件事：停掉当前演出、把时间轴归零、每帧写 `uAscii = 0.95`（写入者
`ascii-demo`）。

**为什么常量要单独写一遍**：模块的 `float` 参数默认值统一是 0，而 `uAsciiContrast = 0` 意味着
**所有格子的亮度都是 0**——只把 `uAscii` 拉到 1 会得到一片纯黑。所以编辑器在加载时就把一组
「装上就能看」的默认值写进总线（行数 54 / 流速 1.4 / 随机度 0.85 / 增益 2.6）。

拖时间轴会自动退出演示：演示与演出是两套语境，同时写同一个 `uAscii` 会触发
`param-conflict`（后者被拒），画面会「卡在某个值」但看不出原因。

## 7. 导出

`serializeTimeline(show, { shock })` 输出一个自包含工厂：

```ts
export const myShow = () => ({
  id: 'my-show',
  duration: 1.9,
  onEnd: 'restore',
  params: (t) => ({ uRimPulseStrength: ..., uDissolve: ... }),
  post: (ctx) => { ... },
});
```

自带 `sample()` 与 `smoothstep`，贴进 `kits/shows.ts` 就能用。**颜色不进采样器**，作为常量闭包进去。

## 9. 已知限制

1. **不能用鼠标转相机**。取景是固定的（正对角色近景），因为这里的判断标准是「字符格和溶解边
   看得清」，不是「房间好看」。要看别的角度去集成编辑器。
2. **不能新增参数**。轨道只能挂到**已声明**的参数上；新效果先写模块（见
   `docs/渲染管线-着色器扩展与钩子系统.md` §5.5），再回来编曲线。
3. **overlay 不参与时间线**。演出里的 `overlay`（DOM 层）没有对应轨道，需要时手写。
4. **导出不回写源码**。和 GLSL 工作台同一个理由：真相只能有一份。导出 → 手动粘贴。
5. **速度滑块不是「只慢演出」**。它缩放的是整条 `dt`。
