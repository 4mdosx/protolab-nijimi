# 角色渲染流程

所有契约角色入口采用同一条链：

**读取角色契约 → 加载可选 SDF → 明确加载状态 → 创建并保留契约的 NPR 材质 → 应用编辑器参数。**

## 职责与接线

1. `src/character.ts` 的 `loadCharacter(id)` 是契约角色资产的唯一加载入口：读取 `<id>.charter.glb`、验证并施加契约、建立表情/指令入口。契约缺失直接报错。
2. `src/character-rendering.ts` 的 `prepareCharacterRendering(character, uniforms)` 按 `character.charter.faceSdf` 加载可选贴图；等待结束后返回 `CharacterRendering`，不把尚未就绪的 SDF 交给材质。
3. 准备阶段统一网格阴影和裁剪策略。face 不叠加 shadow map 的刘海阴影，蒙皮网格不按静态包围盒裁剪。
4. 舞台和动作台调用 `rendering.apply()`；人物编辑器用 `rendering.createMaterial(original)` 创建可缓存的 NPR 对照材质，原材质保持可切回。金属策略默认统一为 `stylizeMetal: false`。
5. 入口最后应用自身参数：朝向、灯光、面部自发光缩放、调试阴影开关等。切换材质模式后重新应用自发光参数，禁止依赖材质转换前的设置。

| 入口 | 接线 |
| --- | --- |
| 人物编辑器 `editors/character.ts` | 加载角色 → 共用准备 → 按当前模式创建/选择材质 → 应用棚拍参数；保留原版、贴图、NPR、Unlit 等对照 |
| 动作台 `editors/pose.ts` | 加载角色 → 共用准备 → `apply()` → 应用自发光和 `?noshadow=1` 等参数 |
| 主舞台 `src/stage.ts` | 加载角色 → 共用准备 → NPR 开启时 `apply()` → 发布角色；通过 `stage.characterRendering()` 查询状态 |
| 场景、集成编辑器 | 复用 `createStage()`；场景编辑器关闭角色时不触发角色加载 |

原版 GLB 和 CC0 对照角色没有契约时，不伪造 SDF 能力，准备状态为 `absent`。材质球查看器是单材质诊断工具，不是角色加载入口；不能代替完整角色的 SDF 校验。

## SDF 状态与回退

`CharacterRendering.faceSdf` 是可判别联合类型：

| `status` | 含义 | 行为 |
| --- | --- | --- |
| `absent` | 契约未声明 SDF | 合法能力缺省，普通 NPR，不发加载失败警告 |
| `ready` | 已加载，并设为 `THREE.NoColorSpace` 数据贴图 | 编译 SDF 变体，绑定真实贴图 |
| `failed` | 契约已声明，但资源加载失败 | 保留 `url` 和 `error`、明确警告、回退普通 NPR |

编辑器准备期间显示加载提示，完成后显示上述状态；不把加载失败伪装成“未声明”。运行期路径仍采用 `/models/<契约声明的文件名>`，由现有资产语料服务提供。

## 编译能力与运行期开关

- `NPR_IS_FACE` 表示 face 材质语义，不依赖是否拥有 SDF。
- `NPR_HAS_FACE_SDF` 表示该材质创建时拥有 SDF；只有此变体才声明 `uNprSdfMap` 并编译采样及 SDF 调试代码。
- `uNprSdfOn` 控制已有 SDF 变体是否使用 SDF；仅将它设为 0 不能代替正确的能力分支。当前材质级绑定覆盖共享默认值，不能把共享容器中的默认值误当作所有 face 材质的总开关。
- 无 SDF 时必须保留基础贴图和普通 NPR，不能让脸部依赖 SDF 才能显示。禁止保留未绑定的活跃 sampler。
- 本流程先等待资源再创建材质。未来若支持热切换 SDF 有无，应重建材质或同步更新 defines、uniform 和 `needsUpdate`；不逐帧改编译宏。

## 契约、模式切换与释放

`toNprMaterial()` 新建的 face、hair/cloth、unlit、outline 材质必须保留 `userData.charter`；PBR 就地注入原本已有契约。后续自发光、表情材质驱动继续读契约，不回退到名字猜测。

`createMaterial()` 先克隆原材质，避免 PBR 就地注入污染“贴图/原版”对照。人物编辑器保留每个模型的转换缓存，换模型时清空，不能复用上个模型的 SDF 或材质。

准备结果的 `dispose()` 负责其加载的 SDF，幂等；网格、几何和材质仍由原有角色持有者释放。编辑器切模型时释放准备结果。快速切模型用请求序号拦截过期结果，调用 `discardPreparedCharacter()` 释放未发布的角色，避免旧请求覆盖当前角色。

## 验证

```bash
npm run check:character-rendering
npm run build
```

自动检查覆盖 SDF 未声明、成功、失败回退，贴图数据色域，SDF 采样器绑定，各轨道契约保留，原材质对照不受污染，重复应用和释放。

浏览器检查人物、动作、集成编辑器：夜兰/祀覆盖有 SDF，明音凛覆盖无 SDF；观察五官、侧面及姿势切换，核对状态。人物编辑器反复切换贴图/NPR 并切模型，检查材质契约、自发光和表情仍生效。场景编辑器不加载角色的模式应照常工作。
