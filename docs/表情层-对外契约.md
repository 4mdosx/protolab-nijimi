# 表情与指令 · 对外契约（`witch.exp/1`）

> **状态：FROZEN**（2026-10-17，契约版本 2）
> 这是消费方（游戏逻辑 / LLM 桥 / 编辑器 / 自动化）唯一被承诺稳定的接口面。
> 设计动机与取舍见 `表情层-系统设计与指令协议.md`；本文件只说**你能用什么、你调不到时会怎样**。

## 0. 三层事实源（改东西之前先看这张表）

| 层 | 文件 | 谁改 | 性质 |
| --- | --- | --- | --- |
| 约定 | `pipeline/expression-rules.mjs` | 人类（资产判断） | 35 个槽位名 / 名字规则 / 各模型档案 / 回退规则 |
| 产物 | `assets/models/expression-manifest.json` | `npm run expr` | 机器可读：每个模型的 binding、target 索引、能力表 |
| 接口 | `src/exp-contract.ts` + `src/exp-protocol.ts` | 只在升版本时改 | 类型、指令、回退语义。**消费方只 import 这两个** |

三条纪律：

1. **槽位名是协议。** 改 `pipeline/expression-rules.mjs` 的槽位名 = 改对外协议，必须升 `EXPR_VERSION` 并同步本文档 §2 的表。
2. **运行期不猜名字。** 一切映射来自 manifest 的 `target: <序号>`；`src/` 里出现 morph 名判定即为违规。
3. **做不到必须报。** 见 §4，回退 + notice 是契约义务，不是最佳实践。

## 1. 指令集

全部是**置位型**指令，不是关键帧。时间语义由引擎兜住（`hold` / `release` / 自动衰减），消费方不需要每帧算权重、也不需要起定时器。

```ts
import type { ExpCommand } from 'nijimi';

exp.apply({ op: 'emote', slot: 'happy', motion: 'wave', hold: 2.0 });
exp.apply([{ op: 'gaze.dir', x: 0.8, y: 0.2 }, { op: 'mouth.set', viseme: 'a', w: 0.7 }]);
```

| op | 参数 | 语义 | 写什么 |
| --- | --- | --- | --- |
| `face.set` | `slot, w?=1, fade?` | 置位并**保持**到下次设置 | morph / 材质 |
| `face.play` | `slot, w?, hold?=1.6, fade?, release?` | 播一次，`hold` 后按 `release` 淡出 | morph / 材质 |
| `face.clear` | `slots?` | 清空指定槽位；省略 = 全清 | — |
| `face.auto` | `what: 'blink' \| 'gaze', on` | 自动眨眼 / 自动视线游移 | — |
| `mouth.set` | `viseme, w?=1` | 口型。`viseme` 接受 `a/i/u/e/o` 或 `mouth_a/mouth_i/...` | morph |
| `mouth.clear` | — | 闭嘴（同时触发口内件隐藏） | — |
| `gaze.dir` | `x, y` | 归一化方向：x 右正、y 上正，长度即强度 | `look_*` morph 或眼骨 |
| `gaze.at` | `target: [x,y,z] \| null` | 看世界一点；`null` = 回空闲 | 同上 |
| `motion.play` | `id, loop?, fade?` | **转交动作系统**，表情层不解释 | 骨骼动画（不在本层） |
| `motion.stop` | — | 停动作 | 同上 |
| `emote` | `slot, motion?, hold?, release?, w?` | 语义打包：「她开心地挥手」 | 表情 + 动作 + 时序 |
| `reset` | — | 表情清空 + 自动层复位 + 停动作 | — |

### 为什么没有 `seq`

`seq`（顺序等待）会引入一个「谁在等谁」的调度器，而表情是**事件驱动**、动作是**采样驱动**，两套时间线混在一个指令里必然要处理取消语义。`emote` 已经把最高频的组合（情绪 + 动作 + 自动回落）包住了；更复杂的编排属于动作系统或游戏侧状态机，不该塞进表情协议。

## 2. 槽位表（35 个，跨模型稳定）

名字一旦定稿就是协议。分七组，组内是「可独立寻址的最小单位」。

| 组 | 槽位 |
| --- | --- |
| `emotion` | `happy` `sad` `angry` `surprised` `relaxed` `shy` |
| `blink` | `blink` `blink_l` `blink_r` |
| `eye` | `squint` `eye_wide` `pupil_small` `highlight_off` |
| `mouth` | `mouth_a` `mouth_i` `mouth_u` `mouth_e` `mouth_o` |
| `look` | `look_u` `look_ur` `look_r` `look_rd` `look_d` `look_dl` `look_l` `look_lu` |
| `brow` | `brow_up` `brow_down` `brow_angry` |
| `symbol` | `symbol_sweat` `symbol_tears` `symbol_vein` `symbol_star_eyes` `symbol_black_line` `symbol_blush` |

`look_*` 是**离散 8 方向**；连续视线用 `gaze.dir`（见 §3）。两者写同一批 target，引擎按 **max** 合成，不叠加。

方向的坐标系是**角色视角**：`x>0` = 角色自己的右方（观众看是画面左），`y>0` = 上。资产侧如果按观众视角命名（`akane` 的 `look_L/R` 就是），manifest 的 `gaze.mirrorX` 会把它翻回来 —— 消费方不需要知道这件事。

## 3. 能力矩阵（这三个模型的事实）

数据来自 `assets/models/expression-manifest.json` 的 `capabilities`，`npm run expr` 生成。**「能做」是资产事实，不是设计意图** —— 换模型只换这张表，指令一个字不用改。

| | `si`（终末地·祀） | `akane`（异环·明音凛） | `yelan`（原神·夜兰） |
| --- | --- | --- | --- |
| 表情层 | ✅ 22/35 | ✅ **35/35** | ❌ 无契约 |
| morph target | 20 | **35** | 0 |
| 视线 | `bone` ±20°（眼球骨 `左目`/`右目`） | `morph` ±18°（8 方向，`mirrorX` 已校正） | ❌ |
| 眨眼 | morph | morph | ❌ |
| 材质通道（脸红） | ✅ 材质 11「表情」 | ❌（脸红走 `TDS_lianhong` morph） | ❌ |
| `emotion` | 6/6 | 6/6 | 0 |
| `blink` / `eye` | 3/3 · 4/4 | 3/3 · 4/4 | 0 |
| `mouth` | 5/5 | 5/5 | 0 |
| `look` | ❌（靠眼骨连续转） | 8/8 | ❌ |
| `brow` | 3/3 | 3/3 | 0 |
| `symbol` | 1/6（仅 `symbol_blush`） | 6/6 | 0 |

**能力矩阵只说明「有没有」，不说明「有多明显」。** `si` 的 `angry` 只移动 180 个顶点（纯眉毛），`happy` 移动 3,386 个（整个眼区）—— 这类差异看 manifest 的 `targets[].affected`，消费方据此决定要不要配姿态或口型。

## 4. 回退与提示（本契约的核心）

调用一个模型不存在的能力时，引擎**按约定回退**，并一定发一条 `ExpNotice`。

### 4.1 三级回退

```
① 直接支持      → 执行
② 同义替代      → 执行 alias，notice = slot-alias
③ 组级中性      → 清掉该组，notice = slot-neutral       ← 「回退到默认」
④ 整个模型无表情 → 丢弃表情部分，notice = no-expression
```

「组级中性」的语义是**清掉**，不是保持上一次 —— 保持会让「她说她生气了」之后一直挂着怒眉。

同义替代只在两个槽位**落在同一份资产**时才登记（否则是骗人）。当前只登记了一对：

```js
symbol_blush → shy     // si 上二者共用材质 11「表情」的同一层 alpha，完全等价
shy → symbol_blush
```

### 4.2 动作的回退

`motion` 由动作系统判断是否存在（`MotionPort.play()` 返回 `false` = 没有）。此时引擎回退到 `MotionPort.idle` 并发 `motion-unavailable`。表情层的默认端口是 no-op 且 `idle='idle'` —— **项目当前没有动作库，所以任何 `motion` 都会如实报「回退到 idle」，而不是假装播了**。

### 4.3 notice 一览

| code | level | 含义 |
| --- | --- | --- |
| `slot-alias` | fallback | 槽位不可用，已用同义槽位替代 |
| `slot-neutral` | fallback | 槽位不可用，该组回到中性 |
| `slot-unknown` | warn | 槽位名不在 35 个里（拼错 / 用了新版本才有的名字） |
| `no-expression` | fallback | 该模型没有表情契约，表情部分整体丢弃 |
| `gaze-unavailable` | fallback | 既无 `look_*` 也无眼骨，视线指令无效 |
| `motion-unavailable` | fallback | 动作系统没有这个动作，回退到 `idle` |
| `unknown-op` | warn | op 不在指令集里（跨版本调用） |
| `contract-version` | warn | manifest 与运行期契约版本不一致（重跑 `npm run expr`） |

消费方拿通知的两种方式（可同时用）：

```ts
const r = exp.apply(cmd);        // ① 返回值：{ ok, applied, notices }
exp.setNoticeSink((n) => ui.log(n)); // ② 回调：UI / 遥测
```

`ok === false` 表示「这条指令降级了」（回退或丢弃），`applied` 是实际生效的槽位。**注意 `ok === false` 不代表出错**，只是没完全照做。

## 5. 版本与变更流程

```
EXPR_CONTRACT_VERSION (src/exp-contract.ts)
      ≡ manifest.contractVersion
      ≡ pipeline/expression-rules.mjs 的 EXPR_VERSION
```

当前 = **2**。三者不一致时运行期 `console.warn` 并在 `checkContract()` 里报出（不致命：表情仍可用，但回退判断可能不准）。

变更分级：

| 改动 | 是否破坏 | 要做什么 |
| --- | --- | --- |
| 加一个可选字段 / 加一个 op | 否 | 升 `EXPR_VERSION`，登记本文档，重跑 `npm run expr` |
| 改槽位名 / 删 op / 改回退语义 | **是** | 升版本 + 本文档写迁移段 + 通知消费方 |
| 只改某个模型的 morph 绑定 | 否 | 改 `expression-rules.mjs` 的 `picks`，重跑 asset 管线 |

管线顺序（改了任何约定之后）：

```bash
node pipeline/pmx2glb.mjs <pmx> assets/models/<id>.glb --expr --model <id>
npm run charter        # 或 node pipeline/charter-glb.mjs assets/models/<id>.glb
npm run expr           # 产出 expression-manifest.json
node pipeline/morph-survey.mjs <pmx>   # 覆盖率体检（只读）
```

## 6. 最小可用示例

```ts
import { loadCharacter } from 'nijimi';

const c = await loadCharacter('akane');
c.exp.setNoticeSink((n) => console.log(n.code, n.detail));

// 一句话：开心 + 挥手，2 秒后自然回落
c.exp.apply({ op: 'emote', slot: 'happy', motion: 'wave', hold: 2.0, release: 0.45 });

// 视线跟随（角色会看向世界坐标里的一点）
c.exp.apply({ op: 'gaze.at', target: [1.2, 1.4, 0.3] });

// 口型：由音频时间线驱动，权重自己算，但时序仍归引擎
c.exp.apply({ op: 'mouth.set', viseme: 'a', w: 0.8 });

// 这个模型做不到的事：一定会拿到 notice，而不是「什么都没发生」
const r = c.exp.apply({ op: 'emote', slot: 'symbol_sweat' });  // si 上 → slot-neutral
```

## 7. 已知缺口

- **`_CLO` 变体仲裁未接**（akane 的 `EL_*_OP/_CLO` 成对）。当前只导 `_OP`，`happy` 的 `EL_Happy_l/_r_CLO` 未使用 —— 眨眼与笑容叠加时眼皮可能穿脸。
- **情绪不做姿态**（按项目决定：姿态归动作系统）。表情层只动脸。
- **`gaze.at` 的头部位置是估值**（包围盒顶部下 6%），没有追头骨。头部大幅转动时视线会有偏差。
- **视线只有 2 个自由度**（yaw / pitch），不做双眼汇聚与眼睑联动。最大角度写在档案里（si ±20°、akane ±18°），
  超出范围按比例**归一化**而不是硬截断 —— 消费方拿到的方向向量长度恒为 1，不用担心越界。
- **`yelan` 永远没有表情**：PMX 源不在库内。
- **动作系统未接入**：`MotionPort` 是占位，所有 `motion` 都会回退 `idle` 并提示。
