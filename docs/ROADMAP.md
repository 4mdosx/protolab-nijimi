# nijimi Roadmap

更新：2026-11-09。性质：用户确认目标下的执行规划；阶段均待核验，不代表运行能力或发布已经完成。

## 1. 当前目标与范围

用 nijimi 完成并发布一款固定场景的风格化小游戏，亲手走通基础资产生产、渲染、交互与交付流程；同期在 Unreal 中完成一个小型对应样例，并参加一次实际协作。

通过作品熟悉渲染技术流与中英文术语，能够定位视觉实现问题，制定项目专用美术管线；以编程与游戏设计为已有基础，补 CG 短板，逐步承担小团队 TA 与主程序职责。

当前发布对象是小游戏，nijimi 提供支撑它的引擎能力。优先固定镜头、单房间、有限对象与单人物。热带工坊的制作/领取/装饰循环仅为候选玩法，需在 M0 选定；发布平台、设备、预算、UE 版本和协作伙伴均待确认。发布方式按平台需求选择，不自动加入服务器或联网。

学习方法唯一入口：`/Users/token/notes/11_learning/TA 入门/00 定位与能力地图：这份教程写给谁、要你变成什么.md` §5；本文件维护实现范围与里程碑。阶段编号取代此前聊天产物中的旧 M0–M7 路线。

## 2. 架构目标与现状边界

```text
场景与规则声明 → Model / Gameplay Systems
                         ↓ 状态 + 事件
                  Presentation Systems
                  动画 / 镜头 / 特效 / 声音
                         ↓
                    Render Backend
```

- Model 保存游戏事实，不持有 GPU、DOM 或 Three.js 对象；交互转换为实体 ID 与 Command，经规则校验更新 Model。
- 状态恢复持续表现，事件触发一次性反馈；模拟时钟与表现时钟有明确暂停和恢复语义，关键奖励不依赖动画回调。
- 采用 Unreal 风格的 Actor / Component 组织语义和 JS 行为；按样例提取最小接口，不以复制完整 Unreal 框架为前置。
- 渲染后端管理材质、Pass 和 GPU 生命周期。现有 ScenePack、材质扩展与冻结表情协议继续使用；此处目标不宣称现有公共 API 已完成隔离。
- 当前接口仍可暴露 THREE；新增面向可迁移行为的接口使用独立数据与句柄，迁移按具体样例验证，不在本轮全面重写兼容面。
- 游戏专有配方、奖励与任务留在消费方；通用能力经验证后进入引擎。小游戏目录/独立仓归属在 M0 决定。

## 3. 里程碑

不按月份承诺；每个阶段留下可运行结果再重构。UE 练习从 M0 穿插，真实协作在 M1 开始寻找与约定，不拖到发布后。

## 4. Blender / Unreal 与协作

Blender 保存源模型、UV、贴图、骨骼和动画；两端共享资产与目标，分别实现材质、灯光和运行行为，记录单位、坐标、旋转、挂点和导入设置差异。

每轮课程只服务一个产物：学 UV 就正确导出一个物件；学材质实例就保存可复现预设；学组件与交互就在 UE 做一项可运行行为。UE 样例服从其实际工作流，不能以 nijimi 风格接口替代成熟引擎实践。

协作最小闭环：与真实他人约定规格和分工 → 接收资产或工程修改 → 定位并反馈问题 → 完成修改与版本交接 → 双方验收。记录职责、版本与结果，不要求公开私人对话；AI 辅助不计作这次真人协作。找不到伙伴时明确记为待完成，不能以个人样例顶替。

迁移能力仅按样例验证：数据可复用、行为需适配、着色与运行时实现可能重写。JS 接入 Unreal 未验证前不承诺直接运行同一脚本。

## 5. 美术管线与诊断契约

- 分开保存源文件与生成产物，记录资产来源及可分发范围；本地研究模型不自动成为发布内容。
- 约定命名、单位、朝向、原点、UV、通道与色彩空间、alpha、材质语义、槽位、动画与预算。
- 通用校验、资产类别规则、风格预设和单资产修正分层；非金属修复、角色薄片 unlit 与 alpha 启发式不无条件用于飞船和全部房间资产。
- 每个视觉问题按镜头/几何 → UV/法线/贴图 → 材质 → 光照 → 透明/阴影/Pass → 输出转换定位，通过单变量对照证伪。
- “半物理”暂指物理光照与材质基础上的艺术化处理，是否包含物理交互在 agent-runner 需求中另行确认。

## 6. 发布与能力验收

- [ ] **学习**：能解释一个效果和关键中英文术语、预测参数变化、复现并排查一次人为故障；生成代码与看完课程不代替掌握。
- [ ] **资产**：至少一个自己走通建模、UV、材质、导出和入库的基础资产；复杂角色无需原创全套。
- [ ] **视觉**：选定参考与默认镜头，对照图记录条件、近似和限制。
- [ ] **玩法**：完整循环、失败/重置、存档与暂停恢复；一次性反馈和奖励不重复。
- [ ] **交付**：可访问发布地址或可取得的发行包、版本说明；外部用户在约定设备运行；关键资源可访问。
- [ ] **性能**：从 M0 记录设备/浏览器/分辨率、帧时间分布、calls/tris、体积和加载条件；GPU 时间与内存仅在可靠可测时报告。预算由实测制定，按瓶颈优化。
- [ ] **工程**：运行/停止/切换资源后释放路径清晰；公共能力与消费方规则分离。
- [ ] **UE 与协作**：对应样例可打开运行并交接，真人协作完成规格、反馈、修改与验收。

每轮引擎改动必须带来作品改进或消除具体制作障碍。优先配置、现有工具与小型实现；重复需求再抽象。不前置通用蓝图、完整物理、联网、WebGPU 重写或通用编辑器。

## 7. 下一步与来源
