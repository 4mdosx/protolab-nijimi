# 职责边界 —— witch-idle × nijimi

---

## 1. 一句话定位

轻量级 WebGL diorama 渲染引擎

## 2. nijimi 导出面（消费方只看这里）

```ts
// 游戏侧拿到的一切渲染能力
import { createStage, workshopScene, THREE } from 'nijimi';
import { assetCorpus } from 'nijimi/vite';          // Vite 插件：/models/** 资产语料映射
```

| 导出 | 层 | 说明 |
| --- | --- | --- |
| `createStage(container, opts)` | 技术层 | 舞台总装：渲染器 / IBL / NPR / 正交 diorama 相机 / 视窗 rig / Bloom + 调色 / 帧循环 / 角色加载 |
| `stage.post`（`PostChain`） | 技术层 | 后期链：具名 pass + 语义锚点（`scene` / `beforeTonemap` / `afterTonemap` / `afterOutput`）。`setEnabled` 只关一段；输出段拆成 `tonemap` + `encode` 两段（结构锚点，锁定）；内容侧加全屏效果走 `post.insert()`，不要自建 composer。RT 挂 `depthTexture`（`reads: ['depth']` 可用，法线缓冲不支持） |
| `stage.effects`（`Effects`） | 技术层 | 演出时间线：真实 dt、`params(t)` 曲线、临时 `post` pass、临时 overlay；参数写入者固定 `fx:<id>`（抢写会被审计拒绝） |
| `stage.params`（`ParamBus`） | 技术层 | 具名 uniform 总线：`uTime`/`uDelta`/`uResolution`/`uCamPos` 由引擎每帧写；`set(id, v, writer)` 带写入者审计 |
| `stage.onFrame(ctx)` / `stage.frame` | 技术层 | 真实时间的每帧钩子 + 只读帧上下文（三时钟见 `src/frame.ts`） |
| `stage.notices` / `onNotice` | 技术层 | 降级提示：`param-conflict` / `module-missing` / `anchor-missing` / `pass-skipped` |
| `extendMaterial` / `ShaderModule` / `registerModule` | 扩展层 | 层 A 注入：模块是纯数据，锚点有守卫，变体键 = 模块签名（同族材质共享 program） |
| `defineMaterial` / `defineMesh` / `patchMaterialSource` | 扩展层 | 层 B 独立材质：参数表自动生成 uniform 声明、内建 `uTime`/相机 uniform、语义队列；`patch` 支持 GLSL 热改 |
| `createShockwavePass` / `createDepthEdgePass` | 技术层 | 成品全屏 pass（`afterTonemap`）；深度描边读 `post.depthTexture` |
| `stage.depth`（`DepthPrepass`）/ `applySoftParticles` | 技术层 | 主渲染**之前**渲的场景深度（半分辨率、只写深度、排除透明件）+ 粒子软淡出；`createStage(..., { softParticles: true })` 打开，内容包从 `ScenePackContext.depth` 拿句柄 |
| `charter.shader.modules` | 契约 | 模型级/材质级的着色模块声明（可选字段）；缺失 = 跳过 + `module-missing`，转换期用 `check:render-modules` 校验 |
| `setQueue` / `QUEUE` | 技术层 | 语义渲染队列：裸 `renderOrder` 一律换成带名（outline / opaque / decal / effect / overlay / screen） |
| `ScenePack`（接口） | 契约 | **引擎与内容之间的唯一分界**，见 §3 |
| `workshopScene` | 内容层 | 引擎自带的示例内容包（工坊 diorama），游戏侧可直接用或整体 fork |
| `THREE`（命名空间） | 技术层 | three.js 再导出——游戏侧拼设备几何时从这里取，**不直接依赖 three** |
| `ConduitManager` / `TABLE_TOP_Y` / `SLOT_PITCH` | 内容层 | 管线 kit 与工坊尺度常量 |
| `charter / npr / character / rig / anim …` | 技术/角色层 | 材质契约、NPR 注入、角色加载、骨骼槽位、外部动画 |
| `nijimi/vite` → `assetCorpus(modelsDir?)` | 工具 | 开发期把 `/models/**` 映射到资产语料目录（默认引擎仓 `assets/models/`） |
| 六台编辑器（`npm run dev` → :5200） | 工具 | 人物 / 姿势动画 / 场景 / 集成 / 着色器 / 演出；标定值回写 `src/*`（着色器工作台例外：只改内存，不回写） |

## 3. ScenePack：引擎与内容的分界

```
引擎（src/stage.ts）  负责「怎么渲」：渲染器/后期/IBL/NPR/相机 rig/帧循环/角色加载
内容包（scenes/*.ts） 负责「有什么」：几何、材质、灯位、锚点、内容动画
```

内容包只要实现 `ScenePack`（`id / span / focus / build(ctx) → { group, handles, update? }`），
就能被同一套舞台 + 编辑器消费，**引擎不用改一行**。取景尺寸（`span`）由内容声明、引擎反推
视锥——「内容有多大」由内容说，引擎不猜。

**内容包迁移路径**（游戏要自建房间时）：

1. 把引擎的 `src/scenes/workshop.ts` 整体 fork 到游戏仓 `src/game/scenes/`；
2. 实现同一个 `ScenePack` 契约；
3. 在 `witch-idle/src/game/scene.ts` 换成自己的包。

游戏侧对渲染的全部接线收敛在 `witch-idle/src/game/scene.ts` 一个文件
（选内容包 + 调 `createStage`）；投影回屏幕这类「渲染职责」走舞台的
`clientPos / objectClientPos`，游戏侧不碰相机与矩阵。

## 4. 资产语料归属

| 前缀 | 位置 | 性质 | 进构建产物？ |
| --- | --- | --- | --- |
| `/models/**` | 引擎仓 `assets/models/`（gitignore） | 契约资产语料：`<id>.glb` 原版 + `<id>.charter.glb` 契约版 + manifest + 动画 GLB。含**不可分发**的拆包模型 | 否（开发期 dev server 直接 serve） |
| `/assets/models/**` | 消费方 `public/assets/models/` | 随包世界通用资产（CC0 可分发） | 是 |

运行期 URL 前缀只有 `/models/**` 与 `/assets/models/**` 两种，引擎与消费方一致；
消费方用 `nijimi/vite` 的 `assetCorpus()` 一行接入，不自己复制映射逻辑。
正式发行时把需要分发的那几个 `.charter.glb` 拷进消费方 `public/assets/models/`。

资产管线（`pipeline/pmx2glb.mjs`、`charter-glb.mjs`、`rig-glb.mjs`、`anim-audit.mjs`…）
与拆包参考（`assets/refs/`）都在引擎仓——**新模型入料是引擎侧动作**，游戏侧只消费产物。


## 5. 运行

```bash
# 引擎（编辑器 / 改渲染时）
cd nijimi && npm install && npm run dev      # 编辑器总览 http://localhost:5200
```

## 6. 角色渲染准备

各入口统一采用「读取角色契约 → 加载可选 SDF → 明确加载状态 → 创建并保留契约的 NPR 材质 → 应用编辑器参数」。实现入口为 `prepareCharacterRendering()`；舞台和编辑器不得重复编写 SDF 加载逻辑。状态、回退、材质对照与资源所有权见 [角色渲染流程](角色渲染流程.md)。
